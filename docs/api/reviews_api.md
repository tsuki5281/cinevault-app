# Reviews Module (API Reference)

## 1. Overview

This module handles the movie reviews feature of the Netflix Review Application using MongoDB.

It allows users to:
- Add a written review for a movie.
- View, edit and delete their own reviews.
- Mark reviews as spoilers and add tags.
- Browse a movie's reviews (newest/oldest, hide spoilers, filter by tag, pagination).
- View review statistics (most-reviewed movies and popular tags).

**Files:**
- `db/mongodb.py`: MongoDB connection, validation rules, indexes and review functions.
- `scripts/init_mongodb.py`: Creates the `reviews` collection with validation rules and indexes.
- `data/reviews.csv`: Review dataset for the first 100 movies (144 reviews, 11 sample users).
- `scripts/convert_reviews_to_mongo.py`: Checks and converts `data/reviews.csv` into typed MongoDB review documents.
- `scripts/tag_reviews.py`: Assigns each review's tags from keywords in its text.
- `docs/review_dataset_notes.md`: Review dataset fields and assumptions.
- `scripts/convert_movies_to_mongo.py`: Converts the MariaDB movie catalogue into MongoDB documents.
- `scripts/performance_mongodb.py`: Index and SQL vs NoSQL performance tests.
- `tests/test_reviews.py`: Unit tests for the reviews module.

## 2. Data Model

**Database:** `netflix_review_db` (set by `MONGO_DB_NAME` in `.env`)

### Collection: `reviews`

| Field | Type | Required | Description |
|---|---|---|---|
| `_id` | ObjectId | Auto | Generated by MongoDB |
| `user_id` | int | Yes | References `users.user_id` in MariaDB |
| `movie_id` | string | Yes | References `movies.movie_id` in MariaDB (e.g. `"s10"`) |
| `review_text` | string | Yes | 1 to 2,000 characters |
| `spoiler` | bool | Yes | `True` if the review contains spoilers |
| `tags` | array of strings | Yes | Lowercase, no duplicates (may be empty) |
| `created_at` | date | Yes | Set when the review is added |
| `updated_at` | date | No | Set only when the review is edited |

**Example document**

```json
{
  "user_id": 1,
  "movie_id": "s10",
  "review_text": "The acting was great, but the ending felt rushed.",
  "spoiler": false,
  "tags": ["acting", "ending"],
  "created_at": "2026-10-27T12:00:00Z"
}
```

### Collection: `movies` (created by the conversion script)

One document per movie, with genres and actors embedded as arrays. Used for `$lookup` in the review statistics and for the SQL vs NoSQL comparison.

```json
{
  "movie_id": "s10",
  "title": "1920",
  "director": "Vikram Bhatt",
  "country": "India",
  "description": "An architect and his wife move into a castle...",
  "genres": ["Horror Movies", "International Movies", "Thrillers"],
  "actors": ["Adah Sharma", "Rajneesh Duggal", "..."]
}
```

## 3. Constraints

| Constraint | How it is enforced | Justification |
|---|---|---|
| One review per user per movie | Unique index `uniq_user_movie` on (`user_id`, `movie_id`) | Same rule as the `ratings` primary key; users edit instead of re-posting |
| Field types and required fields | `$jsonSchema` validator on the collection | MongoDB is schema-less by default; the validator stops bad documents even if code skips the Python checks |
| `movie_id` format | `$jsonSchema` pattern `^s[0-9]+$`, max length 10 | Matches `movies.movie_id VARCHAR(10)` |
| Review length 1 to 2,000 | `$jsonSchema` + Python check | No empty or oversized reviews |
| User and movie must exist | Python check against MariaDB before insert | MongoDB cannot enforce foreign keys to another database |
| Only the author can edit/delete | Reviews are found by (`user_id`, `movie_id`) | Another user's ID never matches the review |

## 4. Indexes

| Index | Fields | Used by |
|---|---|---|
| `uniq_user_movie` | `user_id`, `movie_id` (unique) | `get_review`, `update_review`, `delete_review`, duplicate check |
| `movie_newest` | `movie_id`, `created_at` (descending) | `get_movie_reviews`, `get_review_count` |

## 5. Reviews Management

### `add_review(user_id, movie_id, review_text, spoiler=False, tags=None)`

Adds a new review for a movie by a specific user.

**Parameters**

| Parameter | Type | Description |
|---|---|---|
| `user_id` | int | ID of the user writing the review |
| `movie_id` | str | ID of the movie being reviewed |
| `review_text` | str | Review text (1 to 2,000 characters) |
| `spoiler` | bool | Whether the review contains spoilers (default `False`) |
| `tags` | list of str | Optional tags, e.g. `["acting", "ending"]` |

**Returns**
- `True` if the review is added successfully.
- `False` if the user has already reviewed the same movie.
- Raises `ValueError` if the user ID or movie ID does not exist.
- Raises `ValueError` if any input is invalid (empty text, text too long, wrong types).

**Example**

```python
from db.mongodb import add_review

result = add_review(1, "s10", "Great horror movie!", spoiler=False, tags=["scary"])
print(result)
```

### `get_review(user_id, movie_id)`

Retrieves a user's review for a specific movie.

**Returns**
- A dictionary with `user_id`, `movie_id`, `review_text`, `spoiler`, `tags`, `created_at` and (if edited) `updated_at`.
- `None` if no review exists.

### `update_review(user_id, movie_id, review_text=None, spoiler=None, tags=None)`

Updates an existing review. Only the fields that are given are changed, and `updated_at` is set.

**Returns**
- `True` if the review was updated.
- `False` if the user has no review for this movie (this also stops users editing other users' reviews).
- Raises `ValueError` if no fields are given or any input is invalid.

### `delete_review(user_id, movie_id)`

Deletes a user's review for a specific movie.

**Returns**
- `True` if a review was deleted, otherwise `False`.

## 6. Browsing Reviews

### `get_movie_reviews(movie_id, sort_by="newest", hide_spoilers=False, tag=None, limit=20, offset=0)`

Retrieves the reviews for a movie.

| Parameter | Type | Description |
|---|---|---|
| `movie_id` | str | ID of the movie |
| `sort_by` | str | `"newest"` or `"oldest"` |
| `hide_spoilers` | bool | Leave out spoiler reviews |
| `tag` | str | Only reviews with this tag (not case-sensitive) |
| `limit` | int | 1 to 100 |
| `offset` | int | Number of reviews to skip (pagination) |

**Returns** a list of review dictionaries (empty list if none). Raises `ValueError` for invalid parameters.

### `get_user_reviews(user_id, limit=20, offset=0)`

Retrieves all reviews written by one user, newest first.

### `get_reviews_by_title(title_keyword, hide_spoilers=False, limit=20, offset=0)`

Finds reviews by movie title (partial match, not case-sensitive), newest first. The matching `movie_id`s are looked up in the MariaDB `movies` table, then their reviews are read from MongoDB. Each returned review has an extra `title` field. Returns `[]` if no title matches; raises `ValueError` for an empty keyword.

```python
get_reviews_by_title("idiots")   # reviews of "3 Idiots"
```

### `get_review_count(movie_id)`

Returns the number of reviews for a movie.

## 7. Advanced Queries (Aggregation Pipelines)

| Function | Returns | MongoDB features used |
|---|---|---|
| `get_most_reviewed_movies(limit=10)` | `movie_id`, `title`, `review_count`, `spoiler_count`, `latest_review` | `$group`, `$cond`, `$max`, `$sort`, `$limit`, `$lookup` |
| `get_popular_tags(limit=10)` | `tag`, `count` | `$unwind`, `$group`, `$sort`, `$limit` |

`get_most_reviewed_movies` uses `$lookup` on the `movies` collection to show titles, so run `scripts/convert_movies_to_mongo.py` first.

## 8. Conversion Scripts

### Review dataset (CSV to MongoDB)

`scripts/convert_reviews_to_mongo.py` reads `data/reviews.csv` and converts each row into a typed document: `username` becomes `user_id` (sample users are created in MariaDB if missing), `Yes`/`No` becomes a boolean, `"acting;ending"` becomes an array, and the date (Singapore time) becomes a BSON date in UTC. Rows with an unknown `movie_id`, empty text, a duplicate user-movie pair or an invalid spoiler value are skipped and reported with their line number. See `docs/review_dataset_notes.md` for how the reviews were written.

### Movie catalogue (MariaDB to MongoDB)

`scripts/convert_movies_to_mongo.py` converts the relational catalogue into documents:

| MariaDB (5 tables) | MongoDB (1 collection) |
|---|---|
| `movies` row | One `movies` document |
| `movie_genres` + `genres` | Embedded `genres` array |
| `movie_actors` + `actors` | Embedded `actors` array |

Joins in SQL become embedded arrays in MongoDB, so a movie's details are read in one query with no joins. The trade-off is duplication: a genre or actor name is repeated in every movie document that uses it. The script checks that the MongoDB document count matches the MariaDB movie count.

## 10. Local Setup

1. Install MongoDB Community Server and make sure it is running (`mongodb://localhost:27017`).
2. Install the Python packages: `pip install pymongo python-dotenv`.
3. Add these lines to your local `.env` file:

```
MONGO_URI=mongodb://localhost:27017
MONGO_DB_NAME=netflix_review_db
```

4. Complete the MariaDB setup and import the catalogue first (`python -m scripts.import_movies`).
5. Run from the repository root, in this order:

```powershell
python -m scripts.init_mongodb
python -m scripts.convert_reviews_to_mongo
python -m scripts.convert_movies_to_mongo
python -m tests.test_reviews
python -m scripts.performance_mongodb
```

## 11. Known Limitations

- MongoDB cannot enforce foreign keys to MariaDB. The user and movie are checked when a review is added, but deleting a user or movie in MariaDB does not delete their reviews.
- Each user can only have one review per movie.
- The `movies` collection is a copy of the MariaDB catalogue; rerun the conversion script after the catalogue changes.
- The sample reviews cover the first 100 movies only and were made for this project, because real Netflix user reviews are not publicly available (see `docs/review_dataset_notes.md`).

## 12. Streamlit Integration Updates

The MongoDB review module was integrated with the Streamlit Movie Details interface.

The original review CRUD operations, spoiler filtering, tag filtering, date sorting, pagination and aggregation functions remain available.

### 12.1 Review Retrieval Responsibility

The `get_movie_reviews()` function is responsible for retrieving review documents from MongoDB.

**Function signature**

    get_movie_reviews(
        movie_id,
        sort_by="newest",
        hide_spoilers=False,
        tag=None,
        limit=20,
        offset=0
    )

The supported sorting options are:
- `newest`: Newest reviews first.
- `oldest`: Oldest reviews first.

Other existing functionality remains unchanged:
- Spoiler filtering.
- Tag filtering.
- Pagination using `limit` and `offset`.

Rating retrieval and Highest Rated sorting are handled separately by the Streamlit integration because star ratings are stored in MariaDB.

### 12.2 Application-Level Review and Rating Integration

The Streamlit Movie Details screen uses the following helper:

`get_community_reviews_with_ratings(movie_id, hide_spoilers=True, sort_by="newest", limit=50, offset=0)`

**Location:** `screens/movie_details.py`

This helper combines review documents retrieved from MongoDB with the corresponding users' star ratings retrieved through:

`db.mariadb.get_movie_user_ratings(movie_id, user_ids)`

The combined review dictionaries retain the original MongoDB review fields and include an additional field:

- `rating_stars`: The user's star rating from 1 to 5, or `None` if the user has not rated the movie.

The original MongoDB review documents are not modified when this additional field is added.

### 12.3 Supported Review Sorting

The Streamlit interface provides three sorting options:

| Sorting option | Implementation |
|---|---|
| Newest first | MongoDB sorts by `created_at` descending. |
| Oldest first | MongoDB sorts by `created_at` ascending. |
| Highest rated | Streamlit combines MongoDB reviews with MariaDB ratings and sorts the results. |

For Highest Rated sorting, the application follows these steps:

1. All matching reviews are retrieved from MongoDB in batches of 100.
2. The user IDs associated with the retrieved reviews are collected.
3. MariaDB retrieves their corresponding star ratings using `get_movie_user_ratings()`.
4. Each review is enriched with its `rating_stars` value.
5. Reviews with ratings are displayed before reviews without ratings.
6. Higher star ratings appear first.
7. Newer reviews appear first when ratings are equal.
8. Pagination is applied after the complete matching review set has been ranked.

This ensures that Highest Rated sorting is applied across all matching reviews rather than only the first retrieved page.

For Newest and Oldest sorting, MongoDB continues to handle database-level sorting and pagination directly.

### 12.4 Separation of Database Responsibilities

The revised integration separates numerical ratings from written reviews.

| Database / Module | Responsibility |
|---|---|
| MongoDB (`db/mongodb.py`) | Review documents, review CRUD, spoilers, tags, date sorting and pagination. |
| MariaDB (`db/mariadb.py`) | Numerical star ratings and retrieval of multiple users' ratings. |
| Streamlit (`screens/movie_details.py`) | Combines review documents with their corresponding ratings and handles Highest Rated sorting. |

This removes the direct MariaDB rating lookup from the MongoDB review retrieval function.

However, existing cross-database functionality is preserved where required:

- `_user_and_movie_exist()` continues checking user and movie existence in MariaDB before a review is inserted.
- `get_reviews_by_title()` continues retrieving matching movie IDs and titles from the MariaDB catalogue before retrieving their reviews from MongoDB.

These existing checks are retained because MongoDB cannot enforce foreign keys to the MariaDB database.

### 12.5 Impact on Existing Review Functionality

The following existing functionality remains unchanged:

- Adding, retrieving, updating and deleting reviews.
- One review per user per movie.
- Review text validation and the 2,000-character limit.
- Spoiler identification and filtering.
- Review tags and tag filtering.
- Newest and oldest review sorting.
- Review pagination.
- Most-reviewed movie and popular-tag aggregation queries.

No changes were made to the MongoDB review document structure, collection schema validator or existing indexes as part of this integration cleanup.
